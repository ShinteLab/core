# shogifont パッケージ（と、その CLI である root）

日本語フォントから駒の 14 文字だけを抜き出し、SFEN 表記
(`P,L,N,S,G,B,R,K` / 小文字 / `+` 付き成駒) で表示できる TTF を生成する。
パスは `core/` からの相対で書いている。

- 入力: TTF / TTC / OTF
- 出力: 省略時 `shogi.ttf`。19 グリフのみの軽量 TTF（Noto Serif JP 6MB → 約 13KB）
- 実装は `shogifont/shogifont.go`（name テーブルの読み取りだけ `shogifont/names.go`）。
  依存は `golang.org/x/image`（font/sfnt）のみ

```powershell
go run . [-name FAMILY] [-index N] {inputfont} [output.ttf]
go run . -list {inputfont}      # 書体の一覧（TTC の中身・字が足りるか）
```

## ⚠️ ライブラリと CLI を分けてある（2026-08-16）

**中身は `shogifont` パッケージで、root の `package main` はその薄い CLI でしかない。**
以前はルートの `package main` に全部入っており、**`go run` で叩くことしかできなかった。**

- **理由は ikkyoku の「端末に入っているフォントから駒の字を作る」。** ライセンスの都合で
  同梱できるフォントが限られる（下記）ので、**アプリが動いている端末で焼いて、その端末で
  だけ使う**（再配布しない）という経路が要る。**そのためには import できる入口が要る**
- ⚠️ **ロジックを root に戻さないこと。** 戻すと import する側が消える
- ⚠️ **`Faces` は `Build` の前に呼べること自体が要点。** 端末のフォントは大半が駒の字を
  持たないので、**焼いてみて初めて分かる**のでは一覧に印を付けられない。
  何が足りないかは `Face.Missing`（要る字は `Required()`）
- ⚠️ **name テーブルだけは自前で読んでいる**（`names.go`）。`x/image` の `Font.Name` は
  **言語を選べず、name テーブルに並んでいる順で最初に当たったものを返す** ——
  同じ日本語フォントでも游明朝は `"Yu Mincho"`、玉ねぎ楷書は
  `"Tamanegi Kaisho Geki FreeVer 7"` が返る、という具合に並び順次第で言語が変わる。
  **選ばせる一覧が英語名になったり日本語名になったりして揃わない**ので、
  `Face.LocalFamily`（ja-JP）と `Face.Family`（en-US 優先）を分けて持つ。
  ⚠️ **日本語名が無いときに英語名へ倒さないこと**（`LocalFamily` は空のまま。
  倒すと呼び出し側が「日本語名がある」と誤解する）。読めなければ `x/image` の答えに落ちる
- **`Options.Index` は TTC の中の書体番号。** 以前は先頭決め打ちだったが、
  `msmincho.ttc` のように 1 ファイルに MS 明朝と MS P明朝が同居しているものがあり、
  それでは片方を選べない
- ⚠️ **`Build` は `os.Exit` しない**（旧 `check`/`fatal` は CLI 側へ移した）。
  ライブラリとして呼ぶ側がエラーを画面に出す

## 元フォントを変えて焼き分ける

`-name` が生成フォントの family 名（CSS の `font-family` に出る名前）。
**元フォントを変えるときは必ず変えること。** 同名で複数登録すると
どれが当たるかブラウザ任せになり、切り替えが効かなくなる。

| family | 元フォント | ライセンス |
|---|---|---|
| `ShogiSFEN`（既定） | Noto Serif JP `NotoSerifJP-VF.ttf`（明朝） | **SIL OFL 1.1** |
| `ShogiSFEN Gothic` | Noto Sans JP `NotoSansJP-VF.ttf`（ゴシック） | **SIL OFL 1.1** |

⚠️ **`web/` に足してよいのは、派生物の作成と再配布を認めるライセンスのフォントだけ。**
生成物は元フォントの字形をそのまま持つ派生物を配る行為で、**「手元に入っているから
使える」ではない。** 実際に 3 つ外している:

| 外したもの | 理由 |
|---|---|
| 游明朝 | name 13 が「Microsoft supplied font … **Any other use is prohibited**」 |
| どへた | **改造禁止** |
| 桜鯰毛筆 | **利用規約が存在しない**（許可を確認できない ＝ 使えない） |

- ⚠️ **`fsType` を根拠にしないこと。** 3 つとも `fsType=8`（編集可能な埋め込み許可）だった。
  これは**文書への埋め込み**の話で、派生フォントを作って再配布してよいという意味ではない
- ⚠️ **name テーブルにライセンス条項が無いのは「制約が無い」ではない**
  （どへたの name 13 は TTEdit のシリアルであってライセンスではない）
- ⚠️ **Noto の 2 つはどちらも可変フォントで、既定インスタンスが細い**
  （Serif は ExtraLight / Sans は Thin）。`x/image/font/sfnt` は gvar を解釈しないので、
  **そのまま食わせると細い駒ができる**（見ないと気づきにくい）。
  `fonttools varLib.instancer` で wght=400 を実体化してから渡す
- 生成物は元フォントの copyright / trademark / license / licenseURL を**引き継ぐ**
  （`readSrcNames`）。派生物なので落とさない。焼き直しの手順は `web/README.md` を見ること
- **OFL 1.1 の全文は `web/OFL.txt`**（埋め込んだフォントの由来と権利表記も先頭に記載）。
  ⚠️ **配布物から外さないこと。** OFL がライセンス文の同梱を求めるので、
  `web/package.json` の `files` と `web/assets.go` の `//go:embed` の両方に入れてある
- 既定以外は `web/` で**使う画面だけが読み込むモジュール**に分けてある（`web/README.md`）

⚠️ **上の制約は「core が配るフォント」の話。「端末で焼いて自分で使う」は別の話。**
ikkyoku が `shogifont` を import して端末のフォントから駒の字を作るのは、
**再配布を伴わない**（生成物はその端末から出ない）。**この 2 つを混同しないこと** ——
`web/font*.js` に足してよいかの判断基準を、端末側の生成にまで持ち込むと
**「手元の游明朝で駒を表示する」という正当な使い方まで塞ぐ**ことになる。
逆に、**端末で焼いたフォントを配ってよいわけでもない**（そちらは元フォントの条項が効く）。
`shogifont` はどちらの判断もしない —— **入力に何を渡してよいかは呼び出し側の責任。**

## 文字マッピング (cmap)

| SFEN | グリフ | SFEN | グリフ |
|------|--------|------|--------|
| P/p  | 歩     | G/g  | 金     |
| L/l  | 香     | B/b  | 角     |
| N/n  | 桂     | R/r  | 飛     |
| S/s  | 銀     | K/k  | 王     |

- 大文字（先手）と小文字（後手）は **同じグリフ ID** を指す。フォントでの反転は行わない
- 元の漢字（歩香桂銀金角飛王と杏圭全馬龍）からも cmap で引ける
- スペースと `+` もマッピング済み

### 異体字（`altPieces`）と反転字（`mirroredPieces`）

**同じ駒を別の字で書けるようにグリフを同梱してある。** 玉と左馬の 2 つ。

| 字 | グリフの由来 |
|---|---|
| 玉 | 入力フォントから抽出。「王」を使いたくない人向け |
| 左馬 | 「馬」の輪郭を左右反転して合成（`glyph.mirrored`）。縁起物の飾り駒の字 |

**主な使い道は CSS（stylistic set）。** 利用側が**スタイルを足すだけ**で玉・左馬にできる、
というのがこの機能の目的。

```css
shogi-board { font-feature-settings: "ss01"; }          /* 王 -> 玉 */
shogi-board { font-feature-settings: "ss01", "ss02"; }  /* 玉 + 左馬 */
```

⚠️ **ただし玉を先後で分けるならこれでは足りない。** `K` と `k` は**フォント上で同じグリフ**なので、
盤全体に feature を当てると先手も後手もいっぺんに変わる。片側だけにするには
駒 1 つ 1 つの要素に当てるしかなく、`<shogi-board>` の `gyoku="black"` / `"white"` 属性が
それをやる（`web/README.md`）。**属性名を `K-gyoku` / `k-gyoku` に分ける手は使えない。
HTML の属性名は大文字小文字を区別しない。**

⚠️ **先後を分けられるのは玉だけ。左馬は盤全体。** 玉は王将/玉将という**駒そのものの
呼び分け**（上位者が王）なので片側だけがありうるが、左馬は**盤の見た目の選択**なので、
使うと決めたら両方そうなる。`hidari-uma` を値付きの属性にしないこと。

| | 本文 | 切り替え | 効く場所 |
|---|---|---|---|
| **stylistic set**（主） | `K` / `+B` のまま | CSS `font-feature-settings` | **ブラウザの HTML/SVG のみ** |
| **文字で選ぶ**（予備） | `玉` / U+E000 を描く | 本文を差し替える | **どの描画経路でも**（Canvas 2D・Go の画像生成を含む） |

- **cmap にも字を載せてあるのは予備。** `font-feature-settings` は Canvas 2D と Go の
  `x/image/font` では指定する口が無い（後者はそもそも GSUB を解釈しない）ので、
  そこで玉・左馬が要るようになったら文字で描くしかない。**フォント側は両方積んである**が、
  **今使っているのは CSS の方だけ**（JS 側に対応表は置いていない）
- 玉と左馬で**別のタグ**（`ss01` / `ss02`）にしてあるのは、片方だけ切り替えたいことが
  あるため。1 つの feature にまとめると連動する
- ⚠️ **リガチャの lookup を先頭（index 0）に置くこと。** 適用は lookup の並び順なので、
  先に `+B` を馬にしてからでないと `ss02`（馬 → 左馬）の置換元が現れない
- ⚠️ **フォントを作り分けない。** 生成フラグで `K` の向き先を変える案もあったが、
  そうすると `web/font.js`（base64 埋め込み）まで 2 本になる
- ⚠️ **左馬は Unicode に符号位置が無い。** 「馬を反転して書いたもの」であって別の字ではないため。
  U+E000 はこのフォントが勝手に決めた位置なので、**他のフォントでは全く別の字が出る**。
  描画側は必ず駒フォントを当てた要素の中で使うこと
- 反転は**送り幅の中心**で折り返す（字面の中心ではない）。左右のサイドベアリングが
  入れ替わらないと元の字と重ねたときに位置がずれる
- 他の駒に異体字・反転字が要るようになったら、それぞれの表に足すだけでよい
  （`feature` 欄に新しいタグを書けば lookup も増える）
- ⚠️ **`web/shogi-board.js` の `STYLE` に `font-feature-settings` の既定値を書かないこと。**
  この属性は継承プロパティで、外から当てた指定がシャドウ DOM の中まで届くのが
  「スタイルだけで切り替わる」の仕組み。シャドウ内で宣言すると継承が止まり、
  **利用側の CSS が効かなくなる**（属性を使うときだけ駒ごとにインラインで当てている）
- グリフを足したら `web/font.js` の base64 も焼き直すこと
  （**元フォントは Noto Serif JP**。`web/README.md` 参照）

## 成駒は GSUB リガチャ

`+P` は 2 文字のため cmap では表現できない。GSUB の合字置換（LookupType 4）で
`+` + 基本駒 → 成駒グリフに置換する:

`+P`→と, `+L`→杏, `+N`→圭, `+S`→全, `+B`→馬, `+R`→龍（小文字も同じグリフなので自動対応）

- `liga` と `rlig` 両フィーチャ、`DFLT`/`latn` 両スクリプトに登録 → ブラウザの SVG/HTML でデフォルト有効。
  異体字の `ss01` / `ss02`（単一置換）も同じ GSUB に入っている（上記）
- 入力フォントに `+` が無い場合は十字グリフを合成する（`synthPlus`）

## TTF 生成

`x/image/font/sfnt` は読み取り専用のため、出力 TTF は自前でバイナリ構築している:

- テーブル: cmap (format 4), glyf, loca (long), head, hhea, hmtx, maxp, name, post (v3), OS/2 (v4), GSUB
- グリフ輪郭は `LoadGlyph` を ppem=unitsPerEm で呼んでフォント単位のまま取得。
  座標は y 軸下向きで返るため反転する（`segmentsToGlyph`）
- CFF (.otf) 入力の 3 次ベジェは 2 次に近似変換（`cubicToQuads`、4 分割）— 輪郭がごくわずかに変わりうる
- 組み立ては `assemble`（テーブルソート、チェックサム、head.checkSumAdjustment）

## 検証方法

1. `go test ./shogifont`（`shogifont/shogifont_test.go`）。cmap の割り当て・リガチャ表・
   反転の座標・生成した TTF の再パースまでを見る。**入力フォントを要求しない**（下記）
2. `core/` で `go run . C:\Windows\Fonts\yumin.ttf` で生成
   （⚠️ **これは動作確認。游明朝の派生物は配れない** ——「元フォントを変えて焼き分ける」参照）
3. 生成物を sfnt で再パースし、`PLNSGBRKplnsgbrk+` と漢字のグリフ索引・輪郭・送り幅を確認
   （`玉` が `王`/`K` と**別の GID** になっていること。左馬は `馬` の bbox を
   `[xmin,xmax]` → `[adv-xmax, adv-xmin]` に折り返した値になる）
4. fontTools (Python) で GSUB 構造を確認:
   `python -c "from fontTools.ttLib import TTFont; TTFont('shogi.ttf')"` がエラーなく通り、
   `GSUB` のリガチャに 6 組、feature に `liga`/`rlig`/`ss01`/`ss02` の 4 つ
   （`ss01` = 王→玉、`ss02` = 馬→左馬の単一置換）が定義されていること
5. `test.html` をブラウザで開き、基本駒・成駒（リガチャ）・異体字（玉・左馬）・
   SVG `<text>` の表示を目視確認

### テストが入力フォントを要求しない理由

⚠️ **テストは実在の日本語フォントを読まない。** 手元にどのフォントが入っているかで
結果が変わると、壊れたときにツールの問題か環境の問題か切り分けられないため
（`usi/client` が実機エンジンを要求しないのと同じ理由）。

- 元フォントには `glyphSource`（`func(rune) (*glyph, error)`）越しにしか触らない。
  `buildGlyphSet` がこれを受け取るので、テストは左右非対称な**作り物の輪郭**を返せる
- 字形そのもの（元フォントの馬が正しく抜けたか等）は自動では見ない。そこは目視の担当

## フォントを作り直したら

`web/font.js` / `web/font-gothic.js`（base64 data URL、自動生成）も更新する。
**2 つとも焼き直して `node web/gen-fonts.mjs` を通すこと。** 手順は `web/README.md` を参照。

⚠️ **ikkyoku が端末で焼くフォントはここに関係しない**（ディスクにも残らず、
その端末の webview に `@font-face` で流すだけ）。**焼き直しの手順に混ぜないこと。**
